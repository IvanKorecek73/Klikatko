MOS - nákup testovacího kupónu

Přehled business toku pro vytvoření testovacího kupónu v Core MOS přes SOAP API. Praktické requesty jsou připravené v souboru public/analysis/http/mos-coupon-purchase.http.

Business smysl

Cílem je vytvořit testovací kupón bez zásahu do PidLitacka backendu. Kupón se založí přímo v Core MOS, přiřadí se na vybraný token/identifikátor zákazníka a objednávka se následně označí jako zaplacená kancelářskou platbou.

Klíčové je použití IsTest=true v kroku AddItemToOrder. Tím se kupón vytvoří jako testovací a nemá vstupovat do prodejních statistik a reportů.

Kroky a hodnoty

1. AuthenticateLogin Vrací SessionID. Bez něj nejdou volat další session operace.
2. GetTokens Vybere se token, na který se kupón koupí. Potřebné hodnoty jsou TokenID a CustomerIDx.
3. GetTokenTariffs Vrací možné tarify, zóny, ceny a platnost. Vybraná zóna musí patřit ke stejnému tarifu.
4. AddItemToOrder Vytvoří novou objednávku a vloží testovací kupón. Description ponechat vyplněné.
5. SetOrderPaid Aktivuje kupón potvrzením platby. Používat PaymentType=3 nebo 4.
6. GetCoupons Ověří, že kupón na tokenu skutečně vznikl. Kontrolovat CouponID, OrderID, tarif, zóny a platnost.
Pozor: Core MOS SOAP API vrací HTTP 200 i pro business chyby. V každém kroku je nutné číst Result/ID v SOAP těle. Pokud AddItemToOrder nevrátí Result.ID = 0 a platné OrderID, nepokračujte na SetOrderPaid.
