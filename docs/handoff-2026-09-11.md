## Spuštění Klikátka

- Nainstaluj Node.js. Engine i Redis bridge používají jeho standardní moduly; `node_modules` se nepřenáší.
- Na Windows spusť `Start-Klikatko-Local.cmd` nebo `Start-Klikatko.cmd` v kořeni repozitáře. Výchozí port je 5096.
- Samotný server lze spustit `node server.js`; Redis bridge samostatně `node tools/redis-bridge/src/server.js`.
- Regresní testy bez backendů a emulátoru: `node --test`.

Spouštěče hledají Node.js v uživatelském Codex runtime a potom v PATH. Starý lokální spouštěč
z `_klikatko` je pouze pro zachování historie v `tools/archive/legacy-klikatko/`.

## Lokální konfigurace a přístupy

Vytvoř `public/local/klikatko.local.json` z `config/klikatko.local.example.json` a doplň pouze
potřebné hodnoty ze svého bezpečného zdroje. Na původním zařízení se existující lokální soubor
neměnil ani neodstranil, pouze přestal být sledovaný Gitem. `public/local/` zůstává ignorované.

- `coreMosServiceKey` je servisní klíč Core MOS; potřebuje jej jen příslušný MOS flow.
- `redisConnections` obsahují připojení pro konkrétní prostředí. INT heslo/reference se doplňují lokálně.
- `tools/redis-bridge/.env` a `public/analysis/yaml/` jsou lokální ignorované soubory. Druhý adresář
  obsahuje nasazovací konfiguraci včetně secretů; tyto soubory se v tomto předání nepublikují.
- Přihlášení/relace v browseru, privátní runtime nastavení, Docker volumes a data emulátoru se přes Git
  nepřenášejí. Na novém zařízení se přihlas a připrav odpovídající testovací prostředí.
- Nový HTTP příklad `public/analysis/http/route-recommendations-resolve-int.http` používá
  `PID_TEST_EMAIL` a `PID_TEST_PASSWORD` z prostředí procesu VS Code / REST Client.
- HTTP ukázky `mos-coupon-purchase.http`, `mos-initiate-token-registration.http` a `mos-update-photo.http`
  nově čtou servisní klíč z `CORE_MOS_SERVICE_KEY` v témže procesu. Jejich původní lokální kopie jsou
  zachované v ignorovaném `public/local/http-backup-2026-09-11/`.

Toto předání nepřepisuje starší Git historii; odstranění lokálního souboru z aktuálního stromu
